## 1. Rive

### 1a. Apple runtime (rive-ios / RiveRuntime)
- Current release: **6.30.1**, published 2026-11-13. verified (https://github.com/rive-app/rive-ios/releases, API: repos/rive-app/rive-ios/releases/latest; also `VERSION`/`RiveRuntime.podspec` spec.version "6.30.1")
- Install via SPM: package URL `https://github.com/rive-app/rive-ios`, product `RiveRuntime`. Docs example: `.package(url: "https://github.com/rive-app/rive-ios", from: "6.24.0")`. Docs recommend SPM; CocoaPods is "in maintenance mode". verified (https://www.rive.app/docs/runtimes/apple/apple.md)
- Package.swift is a **binaryTarget** pointing at `https://github.com/rive-app/rive-ios/releases/download/6.30.1/RiveRuntime.xcframework.zip` (prebuilt xcframework, swift-tools 5.10). verified (https://github.com/rive-app/rive-ios/blob/main/Package.swift)
- Platforms: iOS 14.0, visionOS 1.0, tvOS 16.0, **macOS 13.1**, Mac Catalyst 14.0. verified (Package.swift above; same list at https://www.rive.app/docs/runtimes/apple/apple.md). iPadOS is covered by the iOS slice (no separate entry): inference, not stated.
- Licence of runtime: **MIT**, "Copyright (c) 2020 Rive". verified (https://github.com/rive-app/rive-ios/blob/main/LICENSE). README also says "Open-source runtimes, no royalties or runtime fees." verified (https://github.com/rive-app/rive-ios/blob/main/README.md)
- PrivacyInfo.xcprivacy: **yes**, `Resources/PrivacyInfo.xcprivacy` in the repo, bundled by the podspec. Declares `NSPrivacyCollectedDataTypes` = empty array; `NSPrivacyAccessedAPITypes` = one entry, `NSPrivacyAccessedAPICategorySystemBootTime`, reason `35F9.1`. No tracking keys present in the file. verified (https://github.com/rive-app/rive-ios/blob/main/Resources/PrivacyInfo.xcprivacy)
- Telemetry: no telemetry/analytics statement found in the Apple runtime docs or README; the Apple docs page makes no telemetry statement. Not proof of absence in the binary: **not verified** (I did not audit the C++ renderer source or the binary).
- Network calls: Rive's security page states "Can a file make the runtime send network requests? Only for Hosted assets and script fetch." Table: Apple **New Runtime** downloads Hosted assets by default = **No**; Apple **Legacy Runtime** = **Yes**, turn off with `loadCdn: false` on `RiveFile`/`RiveViewModel`. verified (https://www.rive.app/docs/scripting/security.md, section "Hosted assets"). Legacy `RiveViewModel.init(... loadCdn: Bool = true ...)` default confirmed in source (https://github.com/rive-app/rive-ios/blob/main/Source/RiveModel.swift). Script fetch is off until the app turns it on, and "Script fetch is available today in the web runtime and the Rive CLI", not Apple. verified (security.md)
- Load .riv from URL: yes. New API: `File(source: .url(url), worker: worker)`. verified (https://www.rive.app/docs/runtimes/apple/apple.md). README example app also shows "Setting a Rive file via a URL or asset in the bundle". verified (README). Local-bundle loading: `File(source: .local("name", .main), worker:)`. verified (https://www.rive.app/docs/runtimes/apple/loading-assets.md)
- Asset export types (editor inspector dropdown): **Embedded** (default, bytes inside the .riv), **Referenced** (not embedded; app supplies bytes via the asset API/handler; export bundles a zip), **Hosted** (stays on Rive's CDN; "available on paid Voyager plans"). Asset types: image (jpeg/png/webp), font, audio (plus blob in new API). SVGs are converted to vector objects and always embedded. verified (https://www.rive.app/docs/runtimes/apple/loading-assets.md; https://www.rive.app/docs/editor/fundamentals/assets-overview.md line "Hosted: Load the asset from Rive's servers... paid Voyager plans")
- Can CDN be avoided: **yes**. Keep all assets Embedded or Referenced (never Hosted). New Apple runtime "does not automatically fetch hosted assets"; for legacy pass `loadCdn: false`. verified (loading-assets.md; security.md)

### 1d. Runtime features relevant to a procedural morph
- Data binding / View Models: values exposed in the editor connect to properties; types listed include text, number, boolean, color, enum, trigger, **lists, images, artboards**. Apple property wrappers: String/Number/Bool/Color/Image/Font/Blob/List etc. verified (https://www.rive.app/docs/runtimes/data-binding.md; https://www.rive.app/docs/editor/data-binding/overview.md; https://www.rive.app/docs/runtimes/apple/data-binding.md; https://www.rive.app/docs/feature-support.md "Data binding lists, images, and artboards were added after initial data binding support")
- Changing **vector path geometry from app code at runtime** via data binding: **not verified**. No path/vertex property type is listed in the Apple data-binding docs I read. Do not assume it exists.
- Scripting: Rive Editor has Luau scripting incl. **Path Effect scripts**, "Rive scripts that modify and transform path geometry in real-time... warping, distortion, animation, and procedural modifications"; `PathData` exposes moveTo/lineTo/cubicTo/quadTo/close, `contours()`/`measure()`. verified (https://www.rive.app/docs/scripting/protocols/path-effect-scripts.md; https://www.rive.app/docs/scripting/getting-started.md). Scripts are authored in the Rive editor; "Luau scripts and shaders are signed, and runtimes refuse them without a valid signature... Rive compiles that code on its own servers" (so scripted files must be produced via Rive's tooling/servers). verified (https://www.rive.app/docs/scripting/security.md). Scripts run in a sandbox, no network unless app enables script fetch. verified (security.md)
- Can a runtime morph an arbitrary glyph into an arbitrary silhouette with no per-pair authoring? **Docs make no such claim** that I found. What docs do support: authored shape/path animation, path effects (scripted morph logic written once, in-file), data-bound inputs, runtime-supplied images/fonts/artboards/lists. A generic glyph-outline-to-silhouette morph would have to be a path-effect script you write yourself and feed outlines to; whether glyph outlines can be fed in at runtime: **not verified**.

## 2. Unity as a Library (UaaL)

- Docs (Unity 6.0 LTS manual, page "Last updated 18 days ago"): https://docs.unity3d.com/6000.0/Documentation/Manual/UnityasaLibrary.html ; iOS: https://docs.unity3d.com/6000.0/Documentation/Manual/UnityasaLibrary-iOS.html ; Android: https://docs.unity3d.com/6000.0/Documentation/Manual/UnityasaLibrary-Android.html. verified
- Supported platforms for UaaL: **Android, iOS, Windows and UWP**. **macOS is not listed.** verified (UnityasaLibrary.html). Unity versions listed in the manual selector: 6000.0 LTS, 6000.3 LTS, 6000.6 Current, 6000.7 Beta, 7000.0 Alpha. verified (same pages)
- How it works: iOS: build Xcode project from Unity; `UnityFramework` target builds `UnityFramework.framework`; "Unity doesn't place a prebuilt .framework in the export folder"; combine in a workspace. Android: generated Gradle project has a `unityLibrary` module (runtime + Player data) plus thin `launcher` module. verified (iOS/Android pages)
- Known limitations (quoted): "You can't load or integrate more than one instance of the Unity runtime"; native and managed plug-ins may need adapting; "Unity supports only full-screen rendering" on Android and iOS (differs for Unity Industry); after `Application.Unload` Unity "retains memory (between 80 and 180 MB)"; iOS: after `Application.Quit` "you can't reload Unity again in the same app session". verified (UnityasaLibrary.html)
- Size overhead: Unity states no binary-size figure on these pages. Only the 80-180 MB retained memory when unloaded. Binary size: **not verified**.
- Plans/pricing (https://unity.com/pricing, fetched 2026-11-17): Personal Free (gaming/entertainment only); Pro required for businesses over $200K funding or annual revenue, $210/month, from $2,310/yr; Enterprise required for more than $25M annual revenue, custom pricing. verified. Pricing-change page: Pro/Enterprise +5% from January 12th, 2026; "Unity Runtime Fee" cancelled as of September 12, 2024, "will not apply to any games made with Unity 6 or any other version of Unity". verified (https://unity.com/products/pricing-updates). Splash-screen-customisation row exists in the compare table but I could not tell which plans have it from text extraction: not verified.
- Data collection by the Unity runtime:
  - **Engine diagnostics** (crash logs, ANR, error traces) is "one type of Developer Data". Controlled per build profile ("Diagnostic Data Collection" Enabled/Disabled); "If you disable diagnostic data collection in the Editor, Unity stops collecting all diagnostic data from your project", and that "doesn't affect Developer Data collected through other Unity products you use". Project not linked to Unity Cloud => set to Disabled. verified (https://docs.unity.com/en-us/cloud/developer-data/configure-diagnostics-editor ; https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/editor-settings-reference/comp-manager-group/diagnostics-settings ; API: https://docs.unity.com/en-us/engine/6000.7/script-reference/unityeditor/enginediagnostics/enginediagnosticssettings/enabled)
  - Defaults by version, per Unity staff forum posts: 6.2 beta "all new projects will collect diagnostic data by default" (Unity Discussions, 2025-06-24, https://discussions.unity.com/t/introducing-data-controls-and-better-game-diagnostics-in-the-unity-6-2-beta/1658915); 6000.0.70f1 diagnostics "Off... code paths are disabled and stripped unless you turn them on" (post dated 2026-03-10, https://discussions.unity.com/t/support-for-engine-diagnostics-now-available-in-unity-6-0-and-coming-soon-for-22-3/1712274). These are forum posts by Unity staff, not manual pages.
  - **Unity Analytics** (the UGS package) is a separate service. Its FAQ: "Analytics generates an anonymized user ID for each user"; "If your application is a Child App, you need to designate it as such"; "Can I disable Analytics? Yes... from the Settings page on the Unity Dashboard." verified (https://docs.unity.com/ugs/en-us/manual/analytics/manual/faq). It is only active if the package/service is installed and linked: stated default "By default, data collection is enabled" on the Analytics settings page (https://docs.unity.com/ugs/manual/analytics/manual/settings).
  - Unity's Game Player and App User Privacy Policy (Last Updated July 24, 2025; page header "Last Edit/Review: June 30, 2026") section 6 "Our Policies Concerning Children" covers Unity Struckd and Advertising Services; "Our Services are otherwise not intended for children"; "Developers may choose to install a mechanism to opt-out of analytics." verified (https://unity.com/legal/game-player-and-app-user-privacy-policy)
  - Crash reporting in Player Settings (iOS) is a platform crash-report option for Apple's crash reports, not Unity telemetry. verified (https://docs.unity3d.com/6000.0/Documentation/Manual/class-PlayerSettingsiOS.html "Crash Reporting")
  - "Disable HW Statistics": older Editor option; only forum evidence that it was folded into Analytics toggle. **not verified** for Unity 6 (no manual page found).
  - **Can ALL runtime data collection be disabled in a build?** Documented: diagnostics = yes (build profile Disabled); Analytics = yes (don't add the package / disable in Dashboard). A single Unity statement that "a Unity 6 player build with these off sends nothing to Unity at all" was **not found: not verified**. A network-capture test of a built player is the only way to prove it. I did not find a Unity kids/COPPA page for the engine itself (https://unity.com/legal/... children URLs I tried returned 404).
- Apple "commonly used SDKs" list: **UnityFramework is listed**. verified (https://developer.apple.com/support/third-party-SDK-requirements/). So a Unity-as-a-Library iOS build must carry a privacy manifest and signature.

## 3. LibGodot / Godot as a library
LibGodot exists in a stable release. The core PR "LibGodot: Core - Build Godot Engine as a Library" (godotengine/godot#110863, milestone 4.6, merged 2025-10-08) adds `libgodot_create_godot_instance` / `libgodot_destroy_godot_instance` (header `core/extension/libgodot.h`, `@since 4.6`) and a `GodotInstance` class, and the PR text says it supports "Linux, Windows and MacOS" (https://github.com/godotengine/godot/pull/110863). Godot 4.6 shipped 2026-01-26; its release page has an "Introducing LibGodot" section: "With the new LibGodot, you can now embed the engine directly into your own applications" (https://godotengine.org/releases/4.6/ ; release date from https://github.com/godotengine/godot/releases/tag/4.6-stable). Latest stable is 4.7.2 (2026-08-18); the 4.7 release notes page does not mention LibGodot (https://godotengine.org/releases/4.7/), and `libgodot.h` is present in the 4.7-stable tree. Official iOS/Android embedding is not in the stable core PR: follow-ups are still open (e.g. #124015 "LibGodot: Refactor GLES embedding support", #99705 "Enable Godot reinstantiation on iOS for embedding in a single view", #90510 original "Migeran LibGodot Feature"), and the iOS/Android host-embedding status in official stable is **not verified**; stable 4.7 only has placeholder `libgodot.ios.*.xcframework` stubs in `misc/dist/apple_embedded_xcode`. Swift hosting: SwiftGodot (MIT, bindings, https://github.com/migueldeicaza/SwiftGodot) and SwiftGodotKit (MIT, "Embed Godot into Swift apps", latest tag v4.7.3.1, 2026-09-29, https://github.com/migueldeicaza/SwiftGodotKit) which runs on macOS and iOS (iOS device and simulator) but its Package.swift pulls prebuilt xcframeworks from a **fork** (`migueldeicaza/godot` release `v4.7.3-rc-swiftgodotkit.1`), "based on the Godot 4.7 libgodot patches", so it is not stock Godot 4.7.2. Kotlin/Android binding: **not verified** (none found in official godotengine repos; no official Android LibGodot PR found merged).

## 4. Filament (google/filament)
Filament is "a real-time physically based rendering engine for Android, iOS, Linux, macOS, Windows, and WASM... designed to be as small as possible and as efficient as possible on Android"; licence **Apache-2.0**; latest release **v1.81.0** published 2026-11-17, with `filament-android` AAR on Maven Central (`com.google.android.filament:filament-android:1.81.0`) and an iOS archive `filament-v1.81.0-ios.tgz` (https://github.com/google/filament ; https://github.com/google/filament/releases/tag/v1.81.0). It is a 3D PBR renderer, not an animation/vector tool; no Swift/Kotlin 2D path-morph facility claimed.

## 5. Lottie
Lottie (airbnb/lottie-ios 4.6.1, 2026-06-13; airbnb/lottie-android v6.7.1, 2025-10-31) is a library that natively renders vector animations exported as Bodymovin JSON; authored in After Effects via the Bodymovin plugin (also Sketch/Figma exporters named in README); licence **Apache-2.0** for both; platforms: lottie-ios = iOS 15, macOS 10.15, tvOS 13, visionOS 1 (Package.swift); lottie-android = Android (minSdk line in lottie/build.gradle reads 16); also Web/React Native. verified (https://github.com/airbnb/lottie-ios ; https://github.com/airbnb/lottie-android). Lottie has no PrivacyInfo.xcprivacy in the repo root (404 on that path) but "Lottie" is on Apple's required-manifest list: see section 6.
